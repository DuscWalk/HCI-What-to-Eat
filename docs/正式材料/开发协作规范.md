# 开发协作规范

## 1. 分支与提交

- 从最新 `main` 建立任务分支：功能用 `feat/功能`，修复用 `fix/问题`。一个任务一分支，不直接推送 `main`；开发期间及时同步主线，避免长期分叉。
- commit 格式为 `类型: 简短描述`，类型使用 `feat`、`fix`、`refactor`、`docs`、`test`、`chore`。例如：`feat: 增加候选随机建议`、`fix: 修复重复选定记录`、`docs: 补充分工说明`。不强制 scope 或正文，不额外引入提交工具。
- 可以向自己的任务分支推送未完成代码作备份。推送前执行 `git diff`、`git status`，核对本次待推送内容（含已暂存变更和提交）：没有误删、无关修改、敏感信息，也不混入本地环境文件、数据库文件、依赖目录或日志。确需变更的项目依赖声明与锁文件应属于当前任务。

## 2. PR 与合并检查

- 允许自审、自合并，但以下相关检查必须实际完成。未完成、检查失败或尚未验证的 PR 保持 **Draft**，不得合并。
- PR 标题沿用 commit 格式；只有一个 commit 时可以直接复用。PR 描述默认留空，不强制填写验证记录或复述 commit；仅在有未完成事项、特殊操作步骤或跨模块影响时补充必要说明。无需抄录检查结果，不代表可以不做检查。

合并前按任务范围核对：

| 检查项 | 通过标准 |
| --- | --- |
| 类型检查与构建 | 执行项目 README 统一约定的相关命令，退出码为 0 且无错误。当前命令尚未确定，不编造脚本；README 应统一列出命令，没有约定命令不能视为通过 |
| 自动化测试 | 相关测试失败数为 0；本次涉及非平凡业务规则时，对应测试必须实际执行，不能以全部跳过或没有测试视为通过 |
| 页面与 API | 按任务验收操作，核对真实返回数据和业务结果符合预期，不以页面能打开或 HTTP 200 代替验收 |
| 保存与持久化 | 涉及保存时，保存后重查、刷新结果正确；涉及持久化时，重启服务后仍能读到正确数据 |
| 边界与失败 | 相关空数据、非法输入、权限、上限、重复操作等边界按任务覆盖；错误提示符合接口契约，原数据不被误改 |
| 跨模块调用 | 涉及其他模块时实际接通并验证，不能仅凭 mock 通过；纯独立模块不强求无关联调 |
| 数据库变更 | 迁移可从空库初始化，也可从已有开发库升级，不依赖手工改表 |

仅文档等不涉及运行逻辑的任务按实际影响核对内容和格式，不强求无关运行检查；不能借此跳过受影响功能的验证。

## 3. 共享契约与数据库

- 共享字段、接口、业务语义或跨模块调用约定变更，先确认受影响负责人，再同步实现、相关文档和测试，不由单个模块自行改口径。人员职责见[四人开发分工](四人开发分工.md)，字段和协议以 v2 [数据库设计说明](数据库设计说明.md)、[接口契约](接口契约.md)为准；随机由 B 提供 GET /candidates/random，从本人ACTIVE菜品候选均匀抽取，不按报价数加权。
- 修改数据库 schema 必须配套迁移；已合并的迁移不回改，追加迁移修正。数据库变更顺序合并，后合并者先同步主线并调整尚未合并的迁移。
- 共用一份 schema 与迁移历史，各人独立本地数据库，不共享或提交 SQLite 文件。本期不制作/依赖seed、导入或真实数据源；固定测试输入/fixtures/test doubles 是最小单元输入，不是全套模拟库，允许临时测试数据库构造最少数据。每人写本模块迁移和测试，A 统一审核，D 备份审核及确认 A 的变更，受影响模块共同确认契约。
- 用户交付设计即可，四人可直接领任务，不要求用户先实现后台接口、工程、会话或迁移。A 主责最薄后端注册/启动、统一命令和 Prisma 接线；D 主责会话/可信上下文、公共校验错误及前端共享请求；B/C 可先写独立 Service/测试替身。替身通过不替代实际接口与最终联调，空库正常空返回不表示推荐质量已验证。

## 4. 完成标准

功能可运行、相关检查通过、相关文档已同步且 PR 已合并，才算任务完成；推送备份或创建 PR 不等于完成。默认使用 **Squash merge** 合并，合并后删除任务分支。
