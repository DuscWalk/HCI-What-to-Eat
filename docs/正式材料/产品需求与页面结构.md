本文分两部分：**第一部分为产品需求（PRD）**，定义产品做什么、为什么做，有调查数据支撑的条目按标准 PRD 格式给出依据；**第二部分为页面设计**，定义首版页面结构、布局与交互。需求依据的完整论证见《外卖偏好调查结果与开发方向》，本文引用其章节号。

# 第一部分：产品需求

## 一、产品定位

> 当用户还没决定吃什么时，独立 App 根据当下需求和历史偏好，从外卖商家中整理出少量可比较的候选；用户确定后，跳转到原外卖平台完成下单。

- **形态：** 独立的外卖决策辅助 App，位于外卖平台之前的「选择层」。
- **目标用户：** 打开外卖平台时还没想好吃什么，但已有一些要求（如清淡）的人。
- **核心价值：** 减少来回比较和信息查找，给出可撤回的建议，而不是替用户作决定。
- **边界：** 不做商家经营、购物车、优惠核销、支付、配送、订单追踪。

**目标用户依据（§2.3）：** 核心样本 23 人中，11 人属于「没想好吃什么，但有一些要求」，其中 6 人用时超出愿意花的时间；其余 12 人中只有 2 人如此。负担集中在这一群体。

## 二、功能需求

### 2.1 P0：首版必须覆盖

| 编号 | 需求 | 说明 | 依据 |
| --- | --- | --- | --- |
| F1 | 首页浏览流 | 模仿主流外卖平台的浏览体验，展示商家与菜品，支持自由浏览 | §3.1：20/23 人打开平台时未确定餐厅，需要浏览空间 |
| F2 | 本次条件弹窗 | 预算、送达时间、口味等条件，以可跳过的弹窗形式提供，可随时唤起 | §7.2：8 人希望系统只整理关键信息由自己决定；§8.2：少输入 |
| F3 | 推荐弹窗 | 按本次条件从同一数据源筛选出少量候选（默认 3～5 家），可直接加购 | §4.1：18/23 人认真考虑 2～4 家；§7.2：8 人希望约 5 个候选 |
| F4 | 优质复购店提醒 | 优先展示吃过的优质复购店，作为可靠起点和退路 | §7.1：15 人想要复购推荐，0 人反感，为最高优先级 |
| F5 | 低风险尝新 | 候选中固定保留一个低风险尝新选择（熟店新品或可靠新店） | §3.2：13/23 人想尝新但担心踩雷；§4.3：6 人在熟店点新菜 |
| F6 | 候选页（购物车） | 管理已加候选，展示最终价格与送达时间，帮助快速决策。**候选对象为菜品** | §4.2：9/23 人在候选间来回比较，有负担者中 6/8 如此 |
| F7 | 候选数量上限 | 候选集合设数量上限，避免退化为无限收藏夹；满额时给出轻量提示 | §4.1：候选规模集中在 2～4 家 |
| F8 | 候选动态清除 | 候选列表默认按餐次（早/中/晚）动态清除，保持清爽 | 会议决策；与 §4.2「暂存候选回头比较」存在张力，列为待验证 |
| F9 | 候选恢复机制 | 删除的候选可恢复，避免误删 | §8.2：保持可逆 |
| F10 | 记录页 | 列出点过或加入过候选的店铺，支持快速锁定与记忆修正 | §8.1：6 人担心使用历史订单带来不适；§8.2：数据可控 |
| F11 | 记录页数据分类 | 区分「最终选定」「进入候选但未选」「曾点过」三类状态标签 | 会议决策：避免混淆行为记录与长期偏好 |
| F12 | 记录页行为标记 | 支持标记行为原因（如「因赶时间而非偏好」），优化推荐训练数据 | 会议决策：把数据清洗主动权交还用户 |
| F13 | 个性化设置页 | 长期口味偏好、推荐设置（弹窗自动弹出时机、候选上限、候选保留时长、手动清空、随机选择显隐等） | §9：18/23 人愿意提供口味偏好与忌口 |
| F14 | 跳转闭环 | 任何出现店铺的位置均可跳转到对应外卖平台商家页（首版可模拟） | §10.1：形成「选择—比较—跳转」闭环 |
| F15 | 最短决策路径 | 支持直接筛选跳转、候选池跳转、手动选择三条路径，最短三步到达外卖平台 | 会议决策：降低决策成本 |

### 2.3 主动触发的小工具

| 编号 | 需求 | 说明 | 依据 |
| --- | --- | --- | --- |
| F24 | 随机选择 | 从已有候选中随机挑一个，帮助拍板。**默认展示但样式不显眼，用户可在个性化页选择隐藏** | §7.1：随机决定想要 2 人、反感 8 人，不作为默认功能 |

### 2.4 默认关闭或不做

- 自动强制缩小品类；
- 打开 App 立即弹出长问卷；
- 需要大量初始设置的高度定制主页；
- 长文字形式的推荐理由（首版任何位置均不出现）；
- 用户主动手动录入餐厅（会议已降级为非核心需求）；
- 社交分享、吃饭 MBTI 等趣味属性（会议未收敛，搁置）；
- 服务「中途退出导致购物车未清空」的边缘场景（会议决定聚焦核心客群）。

## 三、非功能需求

| 编号 | 需求 | 说明 | 依据 |
| --- | --- | --- | --- |
| N1 | 快速产生价值 | 免注册试用，进入后较短时间内给出第一批候选 | §8.2：独立 App 增加一次切换，需快速见效 |
| N2 | 少输入 | 条件用可跳过的标签，不强制填写 | §8.1：9 人担心需要填写太多信息 |
| N3 | 可逆 | 可继续浏览、删除候选、恢复被排除项 | §8.2：保持可逆 |
| N4 | 延后介入 | 优先在用户主动请求或浏览一段时间后出现 | §7.3：无人希望一打开就出现 |
| N5 | 数据可控 | 历史订单、口味、健康目标分别授权，可临时关闭 | §8.1：6 人担心历史订单带来不适 |
| N6 | 数据解耦 | 数据访问封装为独立接口，界面不直接依赖模拟数据 | §10.2：便于后续替换真实 API |

## 四、推荐逻辑（首版规则，无需机器学习）

1. 预算、距离、送达时间、忌口做硬筛选；
2. 口味、分量、本次目标计算匹配程度；
3. 评分、销量、负面评价降低尝新风险；
4. 历史订单与主动反馈识别可靠复购；
5. 候选中保留熟悉选择、熟店新品、少量可靠新店；
6. 为每个候选生成可读的匹配标签（P1）。

## 五、关键产品决策

| 决策 | 依据 | 取舍 | 待验证 |
| --- | --- | --- | --- |
| 独立 App 形态 | 由课程开发条件决定，问卷未直接验证 | 牺牲「在平台内无缝提示」，换取完整可控的原型闭环 | 切换成本是主要风险（§7.3） |
| 默认给 2～5 个候选，不给单一最优答案 | §7.2：无人希望直接获得最优答案 | 牺牲「一键决定」的便利，换取用户控制感 | 候选过多是否加重比较负担 |
| 条件用可跳过弹窗，不弹长问卷 | §8.1：9 人担心填写太多 | 牺牲信息完整度，换取低门槛 | 条件留空时推荐质量 |
| 首版不出现长文字推荐理由 | 用户浏览时不愿读长文 | 牺牲「解释充分性」，换取界面轻量 | 用户是否仍能理解推荐来源 |
| 随机选择默认展示但样式不显眼 | §7.1：反感 8 人 | 牺牲「一键拍板」的显眼度，换取不违背用户意愿 | 用户是否会主动使用 |
| 记录页支持记忆修正 | §8.1：6 人担心历史订单不适 | 增加编辑成本，换取数据可控与信任 | 用户是否愿意维护记忆 |
| 候选对象为菜品而非店铺 | 会议决策 | 更贴近「这一顿吃什么」，但跨店比较粒度更细 | 菜品粒度是否加重比较负担 |
| 候选按餐次动态清除 | 会议决策 | 保持列表清爽，但可能与「暂存候选回头比较」冲突 | 是否影响跨餐次复用（§4.2） |
| 记录页区分三类状态 | 会议决策 | 展示更清晰，但前端空间有限 | 标签优先级与展示方案 |

## 六、首版原型需要验证的指标

| 指标 | 观察方式 |
| --- | --- |
| 是否缩短超出预期的选择时间 | 实际用时与愿意投入时间的差值 |
| 是否减少页面往返 | 首页、候选页、弹窗之间的切换次数 |
| 是否更容易形成候选 | 用户加入/替换了几家，系统候选被留下多少 |
| 是否更容易拍板 | 已有候选后继续浏览的次数和时长 |
| 是否保留控制感 | 用户是否认为选项足够、能否自由调整 |
| 推荐是否可信 | 用户能否理解推荐来源、是否接受结果 |
| 独立 App 是否值得打开 | 进入 App 到获得第一批有效候选的时间、再次使用意愿 |
| 跳转是否连贯 | 能否从候选页顺利到达对应平台和商家 |
| 过程体验 | 挑选过程满意度与主观费力度 |
| 结果体验 | 刚下单时是想要、够好还是将就 |

# 第二部分：页面设计

首版共 **4 个页面 + 1 个核心弹窗**。导航结构：**记录页与个性化页通过底部栏切换**；**推荐弹窗与候选页通过浮窗快速跳转**。

## 七、页面总览

| 页面 | 定位 | 主要职责 |
| --- | --- | --- |
| 首页 | 浏览流 | 模仿主流外卖平台浏览商家与菜品，是 App 的默认入口 |
| 候选页（购物车） | 决策页 | 从已加菜品候选中快速做出决策 |
| 记录页（Records） | 记忆页 | 快速锁定明确想吃的店；修正推荐记忆 |
| 个性化设置页 | 设置页 | 长期口味偏好与推荐设置 |
| 推荐弹窗 | 核心弹窗 | 按本次条件推荐少量候选，可直接加购 |

## 八、页面详细设计

### 8.1 首页

- **定位：** 模仿美团、饿了么的浏览体验，让用户自由浏览商家与菜品。
- **入口：** App 启动默认进入。
- **出口：** 加购 → 候选页；浮窗 → 推荐弹窗 / 候选页；底部栏 → 记录页 / 个性化页；店铺 → 跳转下单平台。
- **布局：**
  - 顶部：搜索/分类区（浏览流）；
  - 主体：商家与菜品卡片流，每张卡片含店铺名、代表菜品、价格、送达时间；
  - 每张卡片提供「加购」操作，加入候选页；
  - 浮窗：推荐弹窗入口、候选页入口；
  - 底部栏：记录页、个性化页。
- **交互要点：**
  - 浏览到的店可直接加购进候选，首页本身不是候选集合；
  - 首页与推荐弹窗使用同一批数据，弹窗是筛选后的结果；
  - 首页筛选功能中直接展示「点过的店」，复用推荐数据。

### 8.2 候选页（购物车）

- **定位：** 帮助用户从已添加的候选中快速做出决策。**候选对象为菜品。**
- **入口：** 首页浮窗、首页加购、推荐弹窗加购。
- **出口：** 返回首页；店铺 → 跳转下单平台。
- **布局：**
  - 候选列表：每个候选展示**最终价格**与**送达时间**；
  - 数量上限提示（上限值可在个性化页设置）；
  - 随机选择小工具（默认展示、样式不显眼，可在个性化页隐藏）；
  - 返回首页入口。
- **交互要点：**
  - 候选有数量上限，达到上限时给出轻量提示（如「亲，购物车已满」）并引导替换，而非继续添加；
  - 候选列表默认按餐次（早/中/晚）动态清除，保持清爽；保留时长与手动清空在个性化页设置；
  - 删除的候选可恢复，避免误删；
  - 随机选择仅从已有候选中挑一个，作为辅助拍板的小工具；默认展示但样式不显眼，用户可在个性化页选择隐藏。

### 8.3 记录页（Records）

- **定位：** 管理点过或加入过候选的店铺，承担两个功能。
- **入口：** 底部栏。
- **出口：** 返回首页；店铺 → 跳转下单平台。
- **布局：**
  - 店铺列表：按状态分类展示，区分「最终选定」「进入候选但未选」「曾点过」三类标签；
  - 每项支持编辑（修正记忆）与删除；
  - 明确想吃的店可快速锁定并跳转。
- **交互要点：**
  - **功能一：快速锁定。** 用户已明确想吃某家点过的店时，从此页快速找到并跳转，无需重新浏览；
  - **功能二：修正记忆。** 点过或加过候选的店会用于首页推荐与筛选，但有些只是单次妥协，用户可编辑或删除，避免其进入长期推荐依据；
  - 支持标记行为原因（如「因赶时间而非偏好」），优化后续推荐训练数据；
  - 复杂数据（如候选未选）置于后台支撑推荐，前台仅作适度展示。

### 8.4 个性化设置页

- **定位：** 管理长期偏好与推荐行为。
- **入口：** 底部栏。
- **出口：** 返回首页。
- **布局：**
  - 长期口味偏好与忌口；
  - 推荐设置：
    - 推荐弹窗自动弹出时机（浏览多长时间后弹出 / 不自动弹出）；
    - 候选页数量上限；
    - 推荐候选数量（默认 3～5）；
    - 随机选择按钮的显示/隐藏（默认显示）；
    - 候选保留时长与手动清空。
- **交互要点：**
  - 设置项即时生效；
  - 与「数据可控」原则一致，历史订单、口味、健康目标分别授权；
  - 控制设置项数量，避免过多设置引发反感。

### 8.5 推荐弹窗（核心弹窗）

- **定位：** 按本次条件推荐少量候选，是产品的核心决策入口。
- **入口：** 首页浮窗/按钮；个性化页设置的自动弹出。
- **出口：** 加购 → 候选页；点灰色区域 → 返回原页面；店铺 → 跳转下单平台。
- **布局：**
  - 推荐 3～5 家（数量可在个性化页设置）；
  - 展示菜品（候选对象为菜品）；
  - 每个候选提供「加购」操作。
- **交互要点：**
  - **非全屏弹窗：** 背景保留进入弹窗前的页面，仅调灰；
  - **不遮挡底部购物车入口**，购物车保持高亮可见，便于随时跳转；
  - **除购物车外，背景内容不可点击**；
  - 点击灰色区域关闭弹窗，返回原页面；
  - 推荐基于短期/本次口味偏好或特殊选择。

## 九、导航与跳转关系

```text
                    ┌─────────────────────────────┐
                    │           首页               │
                    │  （浏览流 + 浮窗 + 底部栏）   │
                    └─────────────────────────────┘
                       │        │        │      │
        浮窗/按钮 ─────┘        │        │      └──── 底部栏 ────┐
                                │        │                        │
                                ▼        ▼                        ▼
                    ┌──────────────┐  ┌──────────┐      ┌──────────────┐
                    │  推荐弹窗     │  │  候选页   │      │ 记录页 /      │
                    │ （非全屏）    │  │（购物车） │      │ 个性化设置页  │
                    └──────────────┘  └──────────┘      └──────────────┘
                          │ 加购           │ 返回首页            │ 返回首页
                          └───────────────▶│◀────────────────────┘
                                           │
                                           ▼
                                  外卖平台商家页（下单）
```

**跳转规则汇总：**

| 起点 | 终点 | 方式 |

## 十、待验证点

1. 候选页数量上限设为多少合适；
2. 推荐弹窗自动弹出的时机与频率；
3. 条件留空时推荐质量是否可接受；
4. 无长文字推荐理由时，用户能否理解推荐来源；
5. 记录页的记忆修正是否会被用户实际使用；
6. 随机选择小工具是否会被主动使用；
7. 候选按餐次动态清除是否影响跨餐次复用（与 §4.2 存在张力）；
8. 菜品粒度的候选是否加重比较负担；
9. 记录页三类状态标签的展示优先级与视觉方案。
