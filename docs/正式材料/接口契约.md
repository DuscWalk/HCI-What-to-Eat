# 接口契约 v2

## 一、状态与通用协议

本文与[数据库设计说明](数据库设计说明.md)组成包含多平台选择的 v2 实施基线，架构见[技术栈与系统架构](技术栈与系统架构.md)。用户交付仅是设计，不需先实现工程、接口、迁移、session 或数据初始化；四人现在可领任务，用固定测试输入/替身并行开发。本期不制作或依赖 seed、导入或真实数据源。下文 JSON 是格式示例，不是初始化数据。

- 根路径 `/api/v1`，JSON 字段 camelCase；路径 id、shopId、dishId、requestId 为 UUID 字符串。请求体、查询参数及嵌套对象拒绝未知字段；不接受 userId、历史或授权覆盖参数。
- 成功为 `{ "data": ... }`；204 无响应体。分页 data 为 `{items,page,pageSize,total}`，page 默认1且>=1，pageSize 默认20、范围1..100，均整数；total 为过滤后的总数。
- 时间为 UTC RFC3339 毫秒字符串。可空字段明确返回 null；省略请求字段与 null 不混用。金额为整数分，非负数值遵守 Prisma Int 范围。
- 目录按 id 升序；候选按 createdAt 降序、dishId 降序；记录按 occurredAt 降序、id 降序。空目录正常返回空集合，不自动 seed。
- 有 JSON 请求体时要求 `Content-Type: application/json`（允许 charset 参数）；请求体上限64 KiB，其他媒体类型415、超限413。GET 和无体 DELETE 不要求伪造 JSON 请求体。
- 错误结构 `{ "error": { "code": "...", "message": "...", "details": [{"path":"conditions.maxPriceCents","code":"INVALID_TYPE"}] } }`，details 可省略；message 可读，不泄漏 SQL、堆栈、凭证或内部配置。

## 二、会话与访问安全

仅 GET /shops、GET /shops/:id、GET /dishes、GET /dishes/:id 公开；POST /session 负责建立身份，其余均需有效 session。无效/缺失会话返回401，不在其他接口静默新建。

POST /session 请求 `{}`：已有有效会话则复用并返回原 expiresAt，不延期；否则 user、默认 user_settings、session 同事务创建。返回200，data 仅 `{expiresAt}`。凭证是32字节安全随机数的 base64url 编码，Cookie 名 `wte_session`，HttpOnly、SameSite=Lax、Path=/api/v1、无 Domain，HTTPS 下 Secure；固定30天非滑动有效期，Cookie 过期与服务端一致。数据库只存 SHA-256 hex64 摘要，不存或记录原 token。

所有写请求（含 POST /session）校验配置的同源 Origin：缺失、null、不匹配均403 ORIGIN_FORBIDDEN；测试工具也须显式传 Origin。开发通过 Vite 同源代理，不用放开跨域绕过检查。私有资源始终以 session userId 为查询条件，不能仅查 id 后相信客户端归属。

## 三、公共 DTO 的完整字段

以下字段均必返回，标 `| null` 的字段可空；数组不能用 null 代替（菜品未知标签除外）。枚举按列出的字符串校验，不代表数据库自动有 enum 约束。

### 3.1 ShopDTO、DishDTO、OfferDTO 与 PriceEstimate

| DTO | 字段及类型 |
| --- | --- |
| ShopListingDTO | id:string(UUID), shopId:string(UUID), platformCode:"MEITUAN"\|"ELEME", availability:"AVAILABLE"\|"UNAVAILABLE"\|"UNKNOWN", etaMinutes:int\|null, deliveryFeeCents:int\|null, ratingTenths:int\|null, salesCount:int\|null, negativeReviewRatePermille:int\|null |
| ShopDTO | id:string(UUID), name:string, imageUrl:string\|null, category:string\|null, distanceMeters:int\|null, platformListings:ShopListingDTO[], source:"MOCK" |
| OfferDTO | id:string(UUID，dish_listings.id), shopListingId:string(UUID), platformCode:"MEITUAN"\|"ELEME", availability:"AVAILABLE"\|"UNAVAILABLE"\|"UNKNOWN", etaMinutes:int\|null, priceStatus:"COMPLETE"\|"INCOMPLETE"\|"INVALID", price:PriceEstimate\|null, priceIssueCode:"DISCOUNT_EXCEEDS_SUBTOTAL"\|"PRICE_OUT_OF_RANGE"\|null |
| DishDTO | id:string(UUID), shopId:string(UUID), name:string, imageUrl:string\|null, category:string\|null, tasteTags:string[]\|null, allergenTags:string[]\|null, portion:"SMALL"\|"REGULAR"\|"LARGE"\|null, shop:ShopDTO, offers:OfferDTO[], lowestComparableOfferId:string(UUID)\|null |
| PriceEstimate | currency:"CNY", scope:"SINGLE_DISH", estimated:true, components:{dishCents:int\|null,packagingCents:int\|null,deliveryCents:int\|null,discountCents:int\|null}, totalCents:int\|null, missingComponents:("DISH"\|"PACKAGING"\|"DELIVERY"\|"DISCOUNT")[] |

每个 Offer 的 PriceEstimate 四项仅来自其 dish_listing 的菜品价、包装费、模拟已适用优惠及所属 shop_listing 配送费，ETA 也仅取该平台，不跨平台借值。全部已知且金额正确时 priceStatus=COMPLETE；缺项为 INCOMPLETE、totalCents=null，missingComponents 按 DISH、PACKAGING、DELIVERY、DISCOUNT 顺序列出，完整时为空数组。两者 priceIssueCode=null。完整数据优惠大于原合计为 INVALID、price=null、priceIssueCode=DISCOUNT_EXCEEDS_SUBTOTAL；金额越界为 INVALID/PRICE_OUT_OF_RANGE，不能返回负数或夹零。受控写入拒绝错误报价；运行时隔离单条已知坏报价、服务端诊断，不将整列表变成500，真正异常仍返回500。单菜估算不等于多菜整单，不存价格快照、不建券表。

**统一报价出口：** A 在 catalog 维护纯函数 `resolveDishOffers({dish,shopListings,dishListings,offerConditions?})`，输出 `{offers,lowestComparableOfferId,matchingOfferIds,lowestMatchingOfferId}`；estimatePrice 可作为内部计算。首页、推荐、候选比较及预算筛选均复用，不在其他模块直接读价列或前端复制公式。函数独立于 HTTP 和数据来源，可用最小测试输入验证。offerConditions 为 Conditions 中 maxPriceCents/maxEtaMinutes 的可选子集，缺省表示无报价级额外条件；距离、忌口、分量等由调用方在逻辑对象层校验。

平台代码 MEITUAN/ELEME 使用统一静态映射，不建 platforms 表，新增平台须同步 schema 校验及 API 映射。逻辑店/菜跨平台关联不凭同名自动合并；不实现实际来源、外部链接或平台接入。ShopDTO 不再有平台费用/时效顶层字段，DishDTO 不再有单一 price，不保留旧价 fallback。platformListings 与 offers 均按 platformCode、id 升序，缺平台不补造。

Offer 有效 availability 为：店铺或菜品 listing 任一 UNAVAILABLE 则 UNAVAILABLE，双方 AVAILABLE 才 AVAILABLE，否则 UNKNOWN。lowestComparableOfferId 只从 AVAILABLE+COMPLETE 中按 totalCents 升序、etaMinutes 升序（未知末）、platformCode 升序、id 升序取首个；没有则 null。这只是已知可比最低，不断言未知更贵。matchingOfferIds 按 offers 顺序列出同一报价同时满足全部报价条件且 AVAILABLE、非 INVALID 的 id；lowestMatchingOfferId 仅在这些匹配报价的 COMPLETE 项中按同规则取，不能拿全体最低作本次匹配默认。

### 3.2 配置 DTO

SettingsDTO 完整返回以下三个对象，不暴露存储 JSON 字符串：

```json
{
  "preferences": {"tasteTags": [], "avoidTags": []},
  "consents": {"history": false, "taste": false, "healthGoal": false},
  "settings": {
    "candidateLimit": 5,
    "recommendationCount": 3,
    "autoPopupAfterSeconds": null,
    "showRandom": true,
    "candidateRetention": null
  }
}
```

以上也是新身份的技术默认。标签为最多20项的字符串数组，每项 trim 后非空、<=32字符并去重；candidateLimit 整数1..20，recommendationCount 整数1..5且按店数，autoPopupAfterSeconds 为 null 或整数10..3600。授权及 showRandom 为 boolean。candidateRetention 当前仅为 null，表示规则未配置而非永久保留。

PATCH /me/settings 接受非空叶字段子集，如 `{"settings":{"candidateLimit":3},"consents":{"history":false}}`；叶字段合并、数组整组替换，返回完整 SettingsDTO。空对象/无叶字段、错误类型及未知字段400；candidateRetention 非空返回409 CANDIDATE_POLICY_PENDING（保留给尚未配置的策略，不假装接受）。除已注明的两个可空设置外，不接 null。降低上限不删除旧候选，只阻止增量；授权关闭不删除保存数据，后续推荐不用对应数据。

### 3.3 Conditions 与推荐 DTO

Conditions 各字段可省略但不接 null：maxPriceCents、maxEtaMinutes、maxDistanceMeters 为非负 int；tasteTags、avoidTags 为上述标签数组；portion 为 SMALL/REGULAR/LARGE。请求 `{conditions?: Conditions}`，未提供相当于无当次额外条件。

预算和 ETA 须由同一 AVAILABLE 且非 INVALID 的 Offer 同时满足，有对应要求时总价/ETA 须已知；未设预算允许缺价报价匹配，但不能称其最低。例：平台甲20元50分钟、乙30元20分钟，不满足25元且30分钟，不能跨报价拼合。距离为逻辑店铺硬筛选，未知不能通过。有效 avoidTags 非空时，过敏原资料未知不能作为安全通过，有交集必须排除。portion 有要求时未知或不匹配不通过。tasteTags 用于匹配排序，不强行保证命中。

本次 tasteTags 存在（含[]）时替代已授权长期 tasteTags，否则仅在 taste 授权允许时回退；本次 avoidTags 与已授权长期 avoidTags 取并集。关闭授权不阻止用户主动输入当次条件。服务端装载目录、设置和历史上下文，客户端不能自报授权或历史。history=false 不向推荐核心提供 records；开启时也仅提供未删除且 useForRecommendation=true 的记录。

RecommendationDTO：`{items:[{shop:ShopDTO,dishes:[{dish:DishDTO,matchingOfferIds:string(UUID)[],lowestMatchingOfferId:string(UUID)|null}],category:"FAMILIAR"|"FAMILIAR_SHOP_NEW_DISH"|"LOW_RISK_NEW_SHOP"|"GENERAL"}],requestedShopCount:int,noveltySlotFilled:boolean}`。requestedShopCount 来自设置 recommendationCount，同逻辑店一组，dishes 非空，每个 dish 满足逻辑硬条件且 matchingOfferIds 非空；最低匹配报价与 DishDTO 的全体最低明确区分。少于要求不硬凑，空目录 items=[]、noveltySlotFilled=false。不虚构熟店新品或低风险资料，排序权重由 A 维护。

推荐模块不得假定存在菜品级历史：有 dish_id 就用于相应菜品级判断，没有则退化到店铺级；店铺级 SELECTED 不证明某道菜吃过，缺失 dish_id 不得当作新品证据。记录页始终按店铺聚合，选定粒度与 dish_id 是否写入由候选与记录模块负责人决定，不影响可空表结构。

GET /candidates/random 无请求体、无 conditions，返回 `{item:DishDTO|null}`。B 先归一过期，再从本人 ACTIVE 逻辑菜品候选中均匀抽一次，取该菜最新 DishDTO；不按报价数加权，不过滤预算/ETA，无有效报价也仍在抽取集合，由 DTO 展示不可用，不默默删除候选。无有效候选返回 null。除必要过期归一外，不写选择、不改候选、不生成历史、不自动选定。

### 3.4 CandidateDTO 与能力

CandidateDTO：dishId:string(UUID), chosenListingId:string(UUID)|null, chosenListingState:NONE/AVAILABLE/UNAVAILABLE/UNKNOWN/INVALID, status:ACTIVE/DELETED/EXPIRED, createdAt:string(时间), updatedAt:string(时间), statusChangedAt:string(时间), expiresAt:string(时间)|null, removalReason:USER/CLEAR/REPLACED|null, dish:DishDTO, canRestore:boolean, restoreBlockedReason:"POLICY_PENDING"|"NOT_RESTORABLE"|"LIMIT_REACHED"|null。removalReason 区分移除方式。不返回 userId。

chosenListingId=null 为无显式选择，state=NONE，不能视为选择最低报价。有选择时服务端按当前 Offer 算 state：priceStatus=INVALID 优先为 INVALID，否则使用有效 availability。下架/改价保留 id 与候选，不静默换平台或清除选择；chosen 与最低只是不同含义。

候选列表 data 为 `{items:CandidateDTO[],page,pageSize,total,capabilities:{retentionConfigured:boolean,restoreConfigured:boolean}}`。retentionConfigured/restoreConfigured 表示餐次保留/恢复规则是否配置，当前均为 false。canRestore 由服务端按资格与上限计算：ACTIVE 为 false/NOT_RESTORABLE；非 ACTIVE 在恢复规则未配置时为 false/POLICY_PENDING，配置后不具资格为 false/NOT_RESTORABLE、超限为 false/LIMIT_REACHED、可恢复为 true/null。createdAt 是首次关系创建时间，原行用于去重与恢复。

### 3.5 RecordDTO 与 ShopHistoryDTO

RecordDTO：id:string(UUID), requestId:string(UUID), shopId:string(UUID), shopListingId:string(UUID)|null, platformCode:"MEITUAN"|"ELEME"|null, dishId:string(UUID)|null, kind:SELECTED/CANDIDATE_NOT_SELECTED/PREVIOUSLY_ORDERED, source:USER_ACTION/MOCK_HISTORY, occurredAt:string(时间), shopNameSnapshot:string, dishNameSnapshot:string|null, reason:string|null, useForRecommendation:boolean, createdAt:string(时间), updatedAt:string(时间)。platformCode 从不可换绑的店铺 listing 派生，无关联为 null。普通记录数据不返回 userId、deletedAt；列表排除已删，始终按逻辑 shop 聚合，不因平台拆店。

ShopHistoryDTO：shopId:string(UUID), shopName:string, kinds:(SELECTED/CANDIDATE_NOT_SELECTED/PREVIOUSLY_ORDERED)[], counts:{selected:int,candidateNotSelected:int,previouslyOrdered:int}, lastOccurredAt:string(时间)。只统计未删除记录，useForRecommendation=false 的记录仍展示、计数。kinds 按上述枚举顺序只列计数>0的类型。shopName 取该店最新未删记录的店名快照（同时间按记录id降序取首条）。kind 仅筛选哪些店有资格出现，counts/kinds/lastOccurredAt 仍取这些店的全部未删记录。按 lastOccurredAt 降序、shopId 降序分页，total 是店数。

## 四、完整接口矩阵

下表路径均省略 `/api/v1`。查询字符串 `q` 为 trim 后非空、<=100字符的名称包含查询，category 为非空、<=100字符的精确匹配；q/category 省略表示不限，多个过滤条件取交集。分页使用 page/pageSize。查询类型错误及未知字段400。正文 `{}` 表示必须提交空 JSON 对象。

| 方法与路径 | 输入 | 成功 data / 状态 | 关键语义与额外错误 |
| --- | --- | --- | --- |
| POST /session | {} | {expiresAt:string时间}，200 | 建立或复用会话，设置 Cookie；唯一不需既有会话的写接口 |
| GET /shops | q?,category?,分页 | ShopDTO 分页，200 | 公开 |
| GET /shops/:id | 无 | ShopDTO，200 | 公开；不存在404 |
| GET /dishes | shopId?,q?,category?,分页 | DishDTO 分页，200 | 公开；过滤无匹配为空列表 |
| GET /dishes/:id | 无 | DishDTO，200 | 公开；不存在404 |
| GET /me/settings | 无 | SettingsDTO，200 | 完整配置 |
| PATCH /me/settings | 非空叶字段子集 | SettingsDTO，200 | 校验、合并规则见上；策略未配409 |
| POST /recommendations | {conditions?} | RecommendationDTO，200 | 纯计算，无候选或记录写入 |
| GET /candidates/random | 无体、无查询参数 | {item:DishDTO或null}，200 | 需有效会话；先归一过期，从本人有效候选均匀抽取，不产生业务写入 |

| PATCH /candidates/:dishId | {chosenListingId:UUID或null} | CandidateDTO，200 | 仅本人ACTIVE；选择报价或清除显式选择，详细规则见下 |

| POST /candidates/:dishId/restore | {} | CandidateDTO，200 | 关系不存在404；ACTIVE状态冲突409；恢复资格、上限及重新计时规则未配置返回409 CANDIDATE_POLICY_PENDING；超限409 CANDIDATE_LIMIT_REACHED |
| POST /candidates/replace | {fromDishId,toDishId} | CandidateDTO（目标），200 | 原子替换，详细规则见下 |
| POST /selections | {requestId,shopId,shopListingId?:UUID或null} | RecordDTO，新建201、重试200 | 平台可不指定，省略/null归一；不从候选猜平台；店可不在候选，不改候选，不判剩余未选 |
| GET /records/shops | kind?,分页 | ShopHistoryDTO 分页，200 | 店铺聚合，total店数 |
| GET /records | shopId?,kind?,分页 | RecordDTO 分页，200 | 仅当前用户未删单条记录 |

kind 查询只允许三种记录类型。PATCH 本人已删记录返回404。所有私有资源不暴露其他用户的存在性。

### 4.1 候选状态操作

所有计数和读取前先归一 expiresAt<=now 的 ACTIVE 为 EXPIRED；null 暂不清理。ACTIVE 重复 PUT 原样返回，不刷新时间或占额。DELETED/EXPIRED 的 PUT 返回409 CANDIDATE_STATE_CONFLICT，要求走恢复入口。恢复复用原行、保留 createdAt，成功时更新 statusChangedAt/updatedAt、清空 removalReason；恢复资格、上限校验与是否重新计时由候选模块负责人补齐，规则未配置返回409 CANDIDATE_POLICY_PENDING。

PATCH 选择报价仅限本人候选：无关系/其他用户404，非 ACTIVE 409 CANDIDATE_STATE_CONFLICT。chosenListingId 必须提供；null 清除显式选择；非空时 offer 不存在404，属于其他 dish 返回400 VALIDATION_ERROR，非 AVAILABLE 或 INVALID 返回409 OFFER_NOT_SELECTABLE。缺价但 AVAILABLE 可选，明确展示金额未知。仅更新 chosenListingId、updatedAt，不改创建/状态转换/到期时间，不写历史。删除、到期、恢复均不清 chosenListingId；报价下架/改价不静默换平台。

替换两 id 相同400；源不存在404，源非 ACTIVE 409 CANDIDATE_STATE_CONFLICT；目标菜不存在404，目标已 ACTIVE 409 CANDIDATE_STATE_CONFLICT。目标关系若已删/到期，受同样恢复资格与计时规则约束，未配置409 CANDIDATE_POLICY_PENDING，不能绕过恢复校验。成功时源 DELETED/REPLACED，目标 ACTIVE（新目标建行，旧目标复用），数量不增加，因此允许满额或降低上限后仍超额时一换一。任何失败原列表不变（本次事务中归一过期也一并回滚）；后续独立读取仍按实际时间归一。

### 4.2 店铺选定与记录防重

B 调用 C 的记录函数并传同一事务。SELECTED 固定 source=USER_ACTION，服务端取 occurredAt 和必要名称快照，默认店铺级；是否携带 dishId 由 B+C 后定，可空字段已支持，不在本次选择接口增加 dishId。无 dishId 时 dishNameSnapshot 为空。shopListingId 可省略或为 null，归一为空，不从候选猜平台；显式指定则 listing 须存在（否则404）、属于本 shop（否则400 VALIDATION_ERROR）、availability=AVAILABLE（否则409 OFFER_NOT_SELECTABLE）。不指定平台只校验逻辑店存在。可选平台不等于下单；同店下次用新 requestId。

先按会话 userId+requestId 查找（含软删）：同 SELECTED、同 shopId、同归一 shopListingId 返回原记录200，不改时间；payload 不同（含同request换平台）返回409 REQUEST_ID_REUSED；同操作原记录已删返回410 RECORD_DELETED。重试匹配在检查当前可用性之前，成功后平台下架仍可重试。新操作才检查店铺与显式平台并原子写入。并发唯一键冲突重读按同规则返回，不泄漏为500。以后新 requestId 可同店新平台，不存在 user+shop 终身唯一约束。

PREVIOUSLY_ORDERED 仅来自标注的 MOCK_HISTORY；未选记录何时写入由候选与记录模块负责人约定，当前接口不自动产生，不开放任意创建历史或模拟曾点过的 HTTP 接口。

## 五、模块调用与并发约束

推荐模块 A 的核心函数边界为 `recommend({catalog,conditions,context,requestedShopCount,now})`。catalog 是逻辑店铺菜品与平台 listing 资料，通过统一 resolveDishOffers 解析；conditions 是校验合并后的有效条件，context 是 D 按授权装载的可信偏好与 C 提供的历史，now 是统一时间。HTTP 适配层装载上下文，不让客户端传记录或 userId。C 只交付未删且 useForRecommendation=true 的历史；history=false 时根本不提供 records。算法不直接修改候选、记录或授权。随机由 B 提供 GET /candidates/random，不属于推荐核心，不接收 conditions。

SQLite 候选计数、状态写入与候选上限设置变更须使用写事务，先取得写锁，再归一过期、读配置、计数、判断和变更。替换同事务回滚；不能用进程锁声称跨连接正确。数据库忙有界重试整个事务，耗尽503；不要先读后在无锁窗口另写。Prisma 实际锁方式由实现验证，不在文档伪造 API。

## 六、错误码

| HTTP | code | 使用场景 |
| --- | --- | --- |
| 400 | VALIDATION_ERROR | 格式、未知字段、UUID、范围、状态参数或相同替换ID等错误 |
| 401 | SESSION_REQUIRED | 缺失、无效或过期会话 |
| 403 | ORIGIN_FORBIDDEN | 写请求 Origin 缺失、null或不匹配 |
| 404 | NOT_FOUND | 对象不存在或非本人资源 |
| 409 | REQUEST_ID_REUSED | 同用户请求ID用于不同选定payload |
| 409 | CANDIDATE_LIMIT_REACHED | 新增/恢复将超过上限 |
| 409 | CANDIDATE_POLICY_PENDING | 保留配置或恢复资格、上限校验及重新计时规则未配置 |
| 409 | CANDIDATE_STATE_CONFLICT | PUT已删/到期关系须走恢复入口、目标已ACTIVE、替换源非ACTIVE、恢复时已ACTIVE等状态冲突 |
| 409 | OFFER_NOT_SELECTABLE | 候选报价非AVAILABLE或INVALID，或显式选定的平台店铺非AVAILABLE |
| 410 | RECORD_DELETED | 同次选定重试对应的记录已软删 |
| 413 | PAYLOAD_TOO_LARGE | 请求体超过64 KiB |
| 415 | UNSUPPORTED_MEDIA_TYPE | 带体请求不是约定JSON媒体类型 |
| 503 | DATABASE_BUSY | 写事务忙重试耗尽 |
| 500 | INTERNAL_ERROR | 未预期错误或内部无效数据，隐藏实现细节 |
