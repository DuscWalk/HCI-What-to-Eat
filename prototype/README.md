# 首版交互原型

按 `docs/正式材料/产品需求与页面结构.md` 搭的前端原型，只关注页面与交互，数据全部为模拟数据。

## 运行

需要 Node.js 18 及以上。

```bash
cd prototype
npm install
npm run dev        # 开发模式，终端会给出本机和局域网地址，手机可直接访问
npm run build      # 类型检查并打包到 dist/
```

桌面浏览器中显示为手机框，手机浏览器中全屏显示。数据保存在浏览器本地；「个性化 → 演示工具」可以模拟进入下一餐或重置演示数据。

## 页面与需求对照

| 页面 / 组件 | 覆盖需求 |
| --- | --- |
| 首页（`src/pages/HomePage.tsx`、`src/components/HomeTopBar.tsx`） | F1 浏览流，「综合」按长期口味排序；菜品上是「候选」书签开关；店铺卡片标出上架平台和购物车件数；顶部推荐入口 |
| 浮窗（`src/components/CandidateDock.tsx`） | 首页和店铺页边缘的浮球，点一下或往左拉展开成右下角小窗：上半部分是各家店的购物车（直接显示各平台算上券的最低实付），下半部分是候选；不加遮罩，不影响浏览 |
| 推荐弹窗（`src/overlays/RecommendPopup.tsx`） | F2 本次条件（可跳过的标签）、F3 推荐 3～5 个菜品（显示单点最低实付和平台）、F4 常点、F5 尝新位；从顶部入口下方展开、背景调灰、点空白处返回；浮球停在右下角，保持高亮可点 |
| 比一比（`src/pages/CartPage.tsx`、`src/overlays/WheelSheet.tsx`） | 购物车按最低实付排序并标出「这几单最省」；候选部分：F7 上限 3–5 与替换、F8 按餐次清空、F9 最近移出与恢复、F24 转盘 |
| 记录页（`src/pages/RecordsPage.tsx`） | F10 快速锁定、F11 三类状态、F12 标记原因与「不用于推荐」 |
| 个性化页（`src/pages/SettingsPage.tsx`） | F13 长期口味、自动弹出时机、推荐数量、候选上限与保留、随机按钮显隐；N5 分项授权（含「使用各平台优惠券」） |
| 店铺页、确认订单、下单结果（`src/pages/ShopPage.tsx`、`OrderPage.tsx`、`DonePage.tsx`） | 看菜单和各平台菜价、加购物车、改份数、同店加购；底栏和确认订单页直接显示各平台含券实付，默认选最低的平台 |
| 平台收银台（`src/pages/PayPage.tsx`） | F14 跳转闭环：只在付款这一步跳转外卖平台（首版模拟），付款后回到 App |

推荐规则见 `src/logic/recommend.ts`（PRD 第四节的规则版本，不含机器学习）。界面只通过 `src/api/client.ts` 取数（N6），接入真实接口时替换这个文件即可。

## 按小组白板调整的部分

- 推荐入口放在首页顶部（「今天吃什么？帮我挑」），可主动点开，也可在浏览一段时间后自动弹出。
- 长期口味作用于首页浏览流的「综合」排序，含忌口的菜排到店内最后并标出；推荐弹窗以本次（短期）条件为准，本次没选口味时才参考长期口味。
- 随机选择做成候选页顶部的转盘，打开即开始转，只从已有候选中挑。
- 候选上限为 3–5 个；个性化入口使用人形图标。

## 候选与购物车

| | 候选 | 购物车 |
| --- | --- | --- |
| 回答的问题 | 这顿大概吃什么？ | 这家店点哪些菜、各几份？ |
| 范围 | 跨店，以菜品为单位 | 每家店一个 |
| 份数 | 没有，书签式开关 | 有，「− 份数 +」 |
| 上限 | 3–5 个 | 不设 |
| 清空 | 按餐次自动清空 | 下单后清空这家店的 |
| 价格 | 单点时各平台的最低实付 | 整单在每个平台的含券实付，标出最低和差价 |

**最低价**针对购物车：同一家店的菜只选一次，App 按每个上架平台分别计算「菜品小计 + 包装费 + 配送费 − 店铺满减 − 该平台可用的最优一张券」，相当于「每家店 × 每个平台一个购物车」。缺菜的平台标出「缺 N 道菜」，不参与比最低价。价格明细里写明用了哪张券。

模拟数据里多数店同时在美团、饿了么上架，菜价、配送费、满减、送达时间各不相同，部分菜只在一个平台有；优惠券见 `src/api/mockData.ts` 的 `COUPONS`。

## 浮窗交互

- 浮窗默认收成右侧边缘的浮球（数字是购物车数 + 候选数）。点一下，或按住往屏幕中心拉，展开成右下角的小窗；拉得不够远会弹回。
- 小窗不加遮罩，首页照常滚动；购物车一行直接显示最低实付和平台，点它去结算；候选一行可以放进购物车或移出；「全部」进入比一比页。
- 在店铺页，浮球固定停在右下角，避开右侧的加购按钮。
- 收起：点右上角的收起按钮，或按住小窗顶部往右下拖。
- 上下拖动浮球可以换位置；页面滚动时浮球缩进边缘、变半透明，停下后回来，减少遮挡。
- 自动推荐不再直接弹出调灰的弹窗，而是在浏览一段时间后从浮球旁探出一张小卡片，点「看看」才打开推荐。
- 首次进入时浮球旁有一次使用提示。手势之外始终可以点按，键盘也能操作。

## 购买流程

浏览、进店、选菜、购物车、确认订单都在 App 内完成，外卖平台只在最终付款时跳转一次：

```text
浏览 / 推荐（加入候选）→ 候选放进购物车，或进店加购 → 在几家店的购物车之间比最低价
→ 确认订单（默认最低价的平台，可切换）→ 该平台收银台付款 → 回到 App 的下单结果
```

付款完成后记为「最终选定」，这家店的购物车清空，已下单的菜从候选中移出（可在「最近移出」恢复）；结果页可一键清空这一餐剩下的候选。记录页的「再来一单」会把上次的菜放进购物车并直接去结算。

这与 PRD 的产品边界一致：购物车在 App 内完成，App 不做支付，付款跳转到外卖平台。

## 需求文档未定、原型中暂定的做法

- 推荐弹窗「推荐 3～5 家」与「候选对象为菜品」：每家店只出一道菜，以菜品卡片展示。
- 本次条件没有单独做成弹窗，而是放在推荐弹窗顶部，改动后结果即时更新，不点也能直接看推荐。
- 匹配标签属于 P1，未做；只保留「常点」「熟店新品」「口碑新店」三个类型标签，用来区分 F4 和 F5。
- 记录页状态：在 App 内完成付款的店记为「最终选定」，加过候选但没下单的记为「进入候选未选」，只有平台订单的记为「曾点过」。
- 自动推荐默认在首页浏览 1 分钟后探出，每次打开 App 最多一次；用户主动打开过推荐弹窗后不再出现。
